Яагаад хэрэгтэй вэ

Өнөөдрийн бодит асуудал

Систем бүр тусдаа арал

Байгууллага бүр бүртгэл, агуулах, санхүү, баримтаа тус тусын системд хөтөлж, өгөгдөл нь хоорондоо огт ярьдаггүй. Нэг үйлчилгээ авахын тулд иргэн ижил мэдээллээ дахин дахин бөглөдөг.

Төрийн дэд бүтэцтэй холбогдоход хэцүү

ХУР, E-ID, ДАН, e-Barimt-тай холбогдох нь байгууллага бүрт тусдаа хөгжүүлэлт, тусдаа гэрээ, тусдаа зардал. Жижиг байгууллагад бараг боломжгүй.

Монгол хэл хоёрдугаарт

Гадаадын системүүд монгол хэлийг нэмэлт болгож үздэг. Нэр томьёо зөрдөг, баримтжуулалт англиар, дэмжлэг алс холоос ирдэг.

Өртөг ба хараат байдал

Лицензийн төлбөр гадагш урсаж, эх код хаалттай тул байгууллага өөрийн өгөгдөл, өөрийн процессоо ч бүрэн эзэмшдэггүй — vendor lock-in.

Өндөр бүтээмжтэй модуль монолит

Хурд

Сүлжээний хоцролт — 0

Модулиуд нэг бинарид компиллогдож процесс дотроо дууддаг. Микросервисийн хооронд явдаг мянга мянган сүлжээний дуудлага энд огт байхгүй — хамгийн хурдан RPC бол function call.

Уян хатан

Тенант бүрийн апп стор

Аль тенантад аль апп идэвхтэйг PostgreSQL шийднэ — бинари нэг ч, туршлага нь тенант бүрт өөр. Суулгаагүй аппын маршрут 403 хаалттай.

Найдвартай

DAG хамаарал шийдвэрлэлт

Модулийн хамаарлыг Directed Acyclic Graph дээр рекурсивээр шийдэж, мөчлөг илрүүлж, semver шалгана — Odoo-гийн загварыг Go-гийн хурдтай хослуулсан.

Энгийн

Ажиллагааны зардал бага

Нэг контейнер, нэг DB — Kubernetes кластер, service mesh, олон deploy pipeline хэрэггүй. Жижиг баг том платформ ажиллуулж чадна.

Цэвэр

ORM-гүй, ил тод SQL

pgx + гар бичмэл SQL — query бүр ил харагдана, далд N+1 байхгүй, гүйцэтгэл таамаглах боломжтой.

Өргөтгөх

Каталог — цорын ганц эх сурвалж

catalog/apps.json-д апп нэмэхэд SQL гараар бичихгүй — систем өөрөө синк хийнэ. Шинэ модуль = Go interface хэрэгжүүлэх төдий.

Төрийн цахим дэд бүтэц — угсарсан бэлэн

ХУР / XYP

Төрийн мэдээлэл солилцоо

Иргэний бүртгэл (WS100101), хуулийн этгээдийн баталгаажуулалт (WS100201) — маягт бөглөхөд иргэний мэдээлэл автоматаар татагдана. Дахин бичих, алдах зүйл байхгүй.

Үндэсний E-ID

Хуулийн хүчинтэй гарын үсэг

PIN2-оор баталгаажсан QUALIFIED түвшний тоон гарын үсэг — цаасан гарын үсэгтэй адил хуулийн хүчинтэй. Stamp унтарсан ч PAdES fallback-аар баримт гарын үсэггүй үлдэхгүй.

ДАН

Нэгдсэн нэвтрэлт

Mobile OTP, банкны SSO, царай танилт — иргэн өөрийн дассан аргаараа нэвтэрнэ. Платформ өөрөө ч OIDC provider тул бусад системд identity түгээнэ.

e-Barimt

Татварын бүрэн нийцэл

Нэхэмжлэх бүр 10% НӨАТ, e-Barimt баримттай — санхүүгийн ажилтан тусдаа систем рүү орж давхар бүртгэхгүй.

Аюулгүйн баталгаа: E-ID / ДАН / ХУР-ын mock горим зөвхөн хөгжүүлэлтийн орчинд — ENVIRONMENT=production үед автоматаар унтарч, хуурамч мэдээллээр нэвтрэх боломжгүй.

Аюулгүй байдал — давхарласан хамгаалалт

Мөрийн түвшний тусгаарлалт

PostgreSQL row-level security + dbguard: query бүр тенантын хамгаалалттай role дотор гүйнэ. Хөгжүүлэгч WHERE tenant_id мартсан ч өөр байгууллагын өгөгдөл гарахгүй.

Session — цуцлагдах чадвартай

256 битийн санамсаргүй токен, санд зөвхөн SHA-256 хэш нь хадгалагдана. JWT-ийн "цуцалж болдоггүй" сул талаас зайлсхийсэн — нэг товчоор бүх session унтарна.

Нэвтрэлтийн сахилга

bcrypt хэш, IP-д суурилсан rate limit, lockout, constant-time OAuth2 танилт — таамаглах, тулгах халдлагад тэсвэртэй.

Эрхийн нарийн загвар

RBAC — үүрэг, зөвшөөрөл тенант бүрийн хяналтад; эрх тохируулах үйлдэл нь өөрөө админ эрх шаарддаг тул өөрийгөө өргөмжлөх боломжгүй.

Audit бүртгэл

Хэн, хэзээ, юу хийснийг тенант, хэрэглэгч, үйлдлээр нь бүртгэнэ — маргаан гарахад эргэж харах газартай.

CI-д шигтгэсэн шалгалт

Push бүрд gosec, govulncheck, race detector, lint — эмзэг байдал нийлэхээсээ өмнө баригдана. SECURITY.md-ээр зохион байгуулалттай мэдээллийн суваг.

Cloud-native тэсвэрлэлт — ачаалалд бөхийдөггүй

  • Экспоненциал retry — түр зуурын алдааг хэрэглэгчид мэдэгдэхгүйгээр давтан оролдоно.

Ирээдүйн загвар

Зуун repo-г жижиг баг дааж чадах хөгжүүлэлтийн загвар

Release train — 2 долоо хоног

Цөм тогтмол хэмнэлээр semver release гаргана. Distribution бүрд Renovate шинэ хувилбарын PR-ыг автоматаар нээж, CI нь шалгана — цөмийн засвар зуун платформд цагийн дотор тархана.

Upstream-first дүрэм

Цөмд хэрэгтэй засвар зөвхөн цөм рүү PR-аар — хуулбарлаж «түр засах» зам хаалттай. Зуун repo нэг чиглэлд урсана, drift үүсэхгүй.

Шинэ платформ — хагас өдөрт

Template repo + reusable CI: шинэ distribution үүсгэх нь скелет хуулж нэр солих төдий. CI тодорхойлолт нэг газар — засвар нь бүгдэд нэгэн зэрэг.

Хил нь тодорхой

Тенантын шинэ тайлан — өөрийн repo-д, өнөөдөр deploy. Хөдөлгүүрийн шинэ чадвар — цөм рүү PR, дараагийн train-д. Багууд юу хаана амьдардгийг мэднэ.
