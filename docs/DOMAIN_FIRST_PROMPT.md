# Claude Code — Домэйн давхаргыг салгах (1-р алхам: `organisation`)

Апп нь платформыг импортлохоо болих ажлын эхний алхам. Хэлбэрийг нэг
апп дээр батлах нь зорилго; бусад апп нь дараа нь механик ажил. Доорх
prompt-ыг Claude Code-д бүтнээр нь өгнө.

## PROMPT (эндээс доошхыг хуулна)

Чи Gerege Nexus репод ажиллаж байна. Эхлээд контекстоо бүрдүүл:

- `backend/internal/apps/organisation/` — `module.go` (164 мөр),
  `people.go` (559), `reports.go` (194), `module_test.go` (394).
- `backend/pkg/nexus/module.go`, `service.go` — модулийн гэрээ ба
  платформ модульд юу зээлдүүлдэг.
- `backend/internal/apps/boundaries_test.go` — хилийг тестээр барих
  одоо байгаа хоёр шинж чанар, тэдгээрийн бичигдсэн хэв маяг.
- `docs/ECOSYSTEM_GIT_STRATEGY.md` §2.5 (`organisation`-ы мөр, «платформ
  0 апптай асч чаддаг байх нь экосистемийн суурийн шалгуур»),
  §4.1 (хилийг маргалдахын оронд барих).
- `backend/internal/platform/security/security.go:38` —
  `IsValidSlug` нь `pkg/catalog.IsValidSlug` руу дамжуулсан нэг мөр.

Зорилго: `organisation` аппын **бизнес логикийг платформын гэрээнээс
салгаж**, платформ дээр ажиллуулах хэсгийг нимгэн адаптер болгох. Апп нь
Nexus-гүйгээр компайл хийгддэг, тесттэй, ажилладаг байх.

**Таван ажил, таван тусдаа commit.** Ажил 0 нь бусдаас хамааралгүй,
хамгийн түрүүнд орно. Ажил 2 нь Ажил 1-гүйгээр хийгдэхгүй.

### Заавал мөрдөх дүрмүүд

1. Репогийн хэв маяг: `pgx` + гар бичсэн SQL, goose миграц, RLS-д
   найдсан tenant тусгаарлалт. **Шинэ хүснэгт үүсгэхгүй, миграц
   бичихгүй** — энэ бол зөвхөн кодын байршлын өөрчлөлт.
2. **Гадаад зан төлөв нэг ч байтаар өөрчлөгдөхгүй.** Route, JSON
   талбарын нэр, HTTP статус, алдааны текст, permission код, цэсний
   түлхүүр, module ID, `Version()` — бүгд хэвээр. Энэ рефакторыг
   хэрэглэгч мэдэх ёсгүй.
3. **Домэйн пакетын импортын дүрэм — хатуу:**
   - `backend/domain/organisation` (үндсэн хавтас): зөвхөн stdlib.
     `pkg/nexus` ч, `chi` ч, `pgx` ч байхгүй.
   - `backend/domain/organisation/postgres`: stdlib + `pgx`.
   - `backend/domain/organisation/memory`: зөвхөн stdlib.
   - `backend/internal/apps/organisation` (адаптер): `pkg/nexus`, `chi`,
     `domain/organisation`. SQL байхгүй.
   `pkg/nexus`-ыг домэйнд оруулахгүй байгаа нь зориудаар: тэр бол
   платформын гэрээ, түүнийг ярьдаг домэйн нь аль хэдийн платформын
   хэлбэрт орсон домэйн.
4. `domain/` нь `internal/` доор биш — гаднаас импортлогдох ёстой.
   `pkg/` доор ч биш — semver амлалт үүрэхгүй, тэр амлалт нь `pkg/nexus`
   ба `pkg/catalog`-ынх.
5. Шалгалт: `cd backend && go test -race ./... && go vet ./... &&
   golangci-lint run`, мөн доорх grep-шалгуурууд.

### Ажил 0 — `esign`-ыг аппын хувцаснаас гарга

`esign` нь апп биш. `nexus.Register` дууддаггүй, `ID()`/`Menus()`/
`Permissions()` метод байхгүй, `catalog/apps.json`-д ч, ямар ч
манифестад ч байхгүй — 00058 миграцаар `documents`-д шингэсэн бөгөөд
эрхүүд нь `documents.read/sign/manage` болсон. Түүнийг апп мэт харагдуулж
байгаа зүйл нь гурав: `internal/apps/` доторх хавтас, `Module` гэдэг
төрлийн нэр, `RegisterRoutes` гэдэг методын нэр. Гуравуулаа
`nexus.Module`-ын гэрээг дуурайдаг ч тэр гэрээ биш.

1. `git mv internal/apps/esign internal/platform/esign`. Пакетын нэр
   хэвээр. Прецедент нь `internal/platform/staterail` — `egov.Rail`
   төрөл яг ийм шалтгаанаар платформ руу нүүсэн.
2. `type Module` → `type Rails`, `RegisterRoutes(...)` → `Mount(...)`.
   Nexus-ын гэрээг дуурайсан нэр нь тэр гэрээг биелүүлдэггүй төрөл дээр
   байх нь уншигчийг төөрөгдүүлдэг — энэ бол зөвхөн нэрийн засвар,
   гарын үсгийн параметрүүд хэвээр.
3. `documents.go`-гийн `pdf *esign.Module` → `pdf *esign.Rails`,
   импортын зам шинэчлэгдэнэ. Өөр өөрчлөлт байхгүй.
4. `internal/apps/boundaries_test.go`-гийн `crossAppExceptions`-ыг
   **хоосон map** болго. Тайлбарыг шинэчил: онцгой тохиолдол байхгүй
   болсон, учир нь `documents` одоо аппыг биш платформын пакетыг
   импортолж байна.
5. Батал: `esign` нь `internal/apps/`-аас юу ч импортлодоггүй (одоо
   импортолдог долоо нь бүгд платформын пакет), тиймээс «платформ аппыг
   импортлохгүй» гэсэн хоёр дахь шинж чанар эвдрэхгүй. Тестээр батлагдана.
6. `nexus.RegisterReport`-ын хоёр дуудлага хэвээр — бүртгэл нь boot
   дээр буферлэгддэг тул платформын пакетаас дуудагдах нь асуудалгүй.

Энэ ажилд миграц, каталог, эрх, route, зан төлөвийн өөрчлөлт **байхгүй**.
`git mv` + импортын зам + хоёр нэр.

### Ажил 1 — Платформын сүүлчийн импортыг тасал

1. `people.go:315`-ын `security.IsValidSlug(body.Code)` →
   `catalog.IsValidSlug(body.Code)`, импортыг
   `backend/internal/platform/security` →
   `backend/pkg/catalog` болго. Зан төлөв ижил: `security.IsValidSlug`
   нь `catalog.IsValidSlug` руу дамжуулдаг нэг мөр.
2. `internal/platform/security`-г **бүү устга** — платформын өөрийн
   найман файл түүнийг ашигладаг. Зөвхөн `organisation`-ы импорт л
   явна.
3. Батал: `go list -deps ./internal/apps/organisation | grep
   'internal/platform'` — production кодод үр дүн хоосон байна.
   `module_test.go`-ийн `rbac` импорт үлдэнэ, тэр нь зөв: тест нь
   адаптерийг платформтой хамт шалгадаг.

Энэ ажлын дараа `organisation` нь **аль хэдийн** платформгүй, гэхдээ
логик нь HTTP handler дотор хэвээр. Ажил 2 нь түүнийг гаргана.

### Ажил 2 — `backend/domain/organisation` үүсгэ

Гурван файлаас логикийг татаж ав. Одоогийн байдал: `people.go` нь
HTTP декод, SQL, бизнес дүрэм гурвыг нэг функцэд хольсон.

1. **Төрлүүд** (`org.go`): `Person`, `Department` — одоогийн
   `people.go`-гийн JSON тагтай structs. JSON таг **хэвээр**, учир нь
   гадаад гэрээ өөрчлөгдөхгүй.
2. **Порт** (`ports.go`): домэйн өгөгдлийн сангаас юу шаарддагийг
   интерфейсээр зарла. Наад зах нь:
   `ListPeople`, `UpdatePerson`, `SetPersonActive`, `CountAdmins`,
   `ListDepartments`, `CreateDepartment`, `UpdateDepartment`,
   `SetDepartmentArchived`, `DeleteDepartment`, `IsDescendant`,
   `CountChildren`. Нэрсийг одоогийн handler-уудаас гарган ав, шинийг
   бүү зохио.
3. **Домэйн алдаанууд** (`errors.go`): одоо HTTP статусаар илэрхийлэгдэж
   байгаа дүрмүүдийг нэрлэсэн алдаа болго —
   `ErrLastAdministrator`, `ErrSelfDeactivation`, `ErrCycle`,
   `ErrParentArchived`, `ErrUnitNotEmpty`, `ErrDuplicateCode`,
   `ErrInvalidCode`, `ErrCrossTenant`. Одоогийн алдааны **текстийг
   яг тэр хэвээр** нь эдгээрт зөө.
4. **Үйлчилгээ** (`service.go`): дүрмүүд энд амьдарна —
   - өөрийгөө болон сүүлчийн администраторыг идэвхгүй болгохгүй;
   - нэгжийг өөрийнх нь удмын доор зөөхгүй;
   - архивлагдсан эцэгтэй нэгжийг сэргээхгүй;
   - доор нь хүн/нэгж байгаа нэгжийг устгахгүй;
   - код нь `catalog.IsValidSlug`-д нийцнэ.
   Эдгээр нь SQL-ээс биш Go-гоос шийдэгдэнэ; порт нь зөвхөн тоо, мөр
   буцаана.
5. **`postgres/`**: одоогийн SQL-ийг тэр чигээр нь зөө. Query-г бүү
   дахин бич, бүү «сайжруул» — `isUniqueViolation`, `sqlState`,
   `emptyToNil` туслахууд энд ирнэ. `pgx.ErrNoRows`-ыг домэйний алдаа
   болгож хөрвүүлэх нь энэ давхаргын ажил.
6. **`memory/`**: ижил портын map-д суурилсан хэрэгжилт. Энэ нь
   домэйний тестийг Postgres-гүйгээр ажиллуулах зорилготой, production-д
   хэрэглэгдэхгүй — файлын толгойд тэгж бич.
7. **`service_test.go`**: дээрх таван дүрэм тус бүрд нэг тест,
   `memory/` дээр. `go test ./domain/...` нь `DATABASE_URL`-гүйгээр
   ногоон байх ёстой.

### Ажил 3 — Адаптерийг нимгэн болго

1. `internal/apps/organisation/module.go` — `nexus.Module`-ын долоон
   метод хэвээр. `New(p nexus.Platform)` нь
   `organisation.NewService(postgres.New(p.DB()))` угсарна.
2. `http.go` (шинэ, `people.go`-г орлоно) — handler бүр гурван зүйл
   хийнэ: декод, домэйн дуудах, домэйний алдааг HTTP статус болгох.
   Алдааны зураглал нэг газар:
   ```go
   func status(err error) int  // ErrCycle → 409, ErrCrossTenant → 404, ...
   ```
   Одоогийн handler бүрийн буцаадаг статусыг мөр мөрөөр нь тулгаж
   баталгаажуул. **Нэг ч статус өөрчлөгдөх ёсгүй.**
3. `reports.go` — **адаптерт үлдэнэ**. Тайлан нь `nexus.Querier`,
   `nexus.ParamSpec`, `nexus.ColumnSpec` ярьдаг, өөрөөр хэлбэл
   платформын чадвар. Домэйнд оруулбал §3-ын импортын дүрэм унана.
4. `module_test.go`-д **гар бүү хүр**. Түүний зургаан тест
   өөрчлөгдөөгүй байж ногоон байх нь энэ рефакторын гол нотолгоо: зан
   төлөв хадгалагдсан гэдгийг өөр юу ч батлахгүй.

### Ажил 4 — Хилийг тестээр бари

1. `backend/domain/boundaries_test.go` — `internal/apps/boundaries_test.go`-ийн
   хэв маягаар (`build.Import`, шалтгаан бүхий exception map, шалтгааныг
   комментоор биш тестэд бичих). Шинж чанар:
   - `domain/` доорх пакет `internal/`-ыг импортлохгүй;
   - `domain/` доорх пакет `pkg/nexus`-ыг импортлохгүй;
   - `domain/<app>` үндсэн хавтас нь `pgx`-ийг ч импортлохгүй
     (зөвхөн `postgres/` дэд пакет импортолно).
   Алдааны мессеж нь юу эвдэрснийг биш **яагаад тэр дүрэм байгааг**
   тайлбарлана — байгаа хоёр тестийн бичлэгийг үлгэр болго.
2. CI: `.github/workflows/ci.yml`-ийн **`Lint`** ажилд шинэ алхам нэм
   (өгөгдлийн сан хэрэггүй, тиймээс `Test` биш).
   ```bash
   go list -deps ./domain/... | grep -q 'open-gerege-nexus/backend/internal' \
     && { echo "домэйн платформыг импортоллоо"; exit 1; }
   go list -deps ./domain/... | grep -q 'open-gerege-nexus/backend/pkg/nexus' \
     && { echo "домэйн SDK-г импортоллоо"; exit 1; }
   ```
   Тест байхад CI мөр илүүц санагдаж болох ч биш: тест нь Go-гийн мэдэх
   импортыг барина, энэ хоёр мөр нь `go.mod`-ын түвшинд барина. Хэв
   маяг нь ижил файл дахь «Fail if the … tests were skipped» алхмуудынх
   — чимээгүй өнгөрөхийн оронд чанга унадаг шалгалт.
3. `docs/adr/` хавтас **шинээр** үүснэ; эхний баримт нь
   `docs/adr/0001-domain-first.md`. Агуулга:
   - Дүрэм нэг өгүүлбэрээр: *домэйн бол хаана ажиллахаас үл хамааран
     үнэн зүйл; адаптер бол хаана ажиллаж байгааг мэддэг бүх зүйл.*
   - **Онцгой тохиолдол байхгүй.** `internal/apps/` доторх бүхэн энэ
     хэлбэрт орно; дараалал нь зөвхөн зардлаар тодорхойлогдоно.
     `esign` нь жагсаалтад байхгүй, учир нь тэр Ажил 0-д апп байхаа
     больсон — хасагдсан биш, өөр давхарга болсон.
   - «Салгах» гэдэг үг хоёр зүйл хэлдгийг тодруул.
     `docs/ECOSYSTEM_GIT_STRATEGY.md` §2.5-д тэр нь **өөр репод
     гаргах** гэсэн утгатай — тэгвэл долоон хамаарал `pkg/nexus`-ын
     semver-т хөлдсөн гэрээ болно, тэр үнэтэй. Домэйн/адаптерын
     хуваалт тэрнээс өөр: порт нь `domain/<app>/ports.go` дотор,
     SDK-д биш, semver үүрэхгүй, гаднаас хэн ч импортлохгүй, адаптер
     нь `internal/platform/*`-ыг чөлөөтэй импортлосон хэвээр.
   - Интерфейсийн шөлнөөс сэргийлэх дүрэм: **порт бүр production биш
     дор хаяж нэг хэрэгжилттэй байх ба тэр нь бодит тестэд
     ашиглагдана.** Хоёр дахь хэрэгжилтийг бичиж чадахгүй бол хил
     олоогүй, зүгээр нэг функцийг боож ороосон байна.
   - `crossAppExceptions` Ажил 0-д хоосорсныг тэмдэглэ: онцгой
     тохиолдлыг зөвтгөх шаардлагагүй болсон, учир нь `documents` одоо
     аппыг биш платформын пакетыг импортолж байна.
   CHANGELOG-д мөр нэм.

## Дараагийн алхмууд (энэ prompt-д ороогүй)

Хэлбэр батлагдсаны дараа хэмжсэн дараалал. Тоо нь production кодын
платформын импортын тоо:

| Апп | Импорт | Мөр | Тэмдэглэл |
| --- | --- | --- | --- |
| `reports` | 2 | 1111 | `reporting` бол платформын хөдөлгүүр — зөвхөн апп талыг нь салга |
| `egov` | 4 | 302 | `gerege`, `staterail` нь порт болно |
| `documents` | 5 | 3541 | `dan`, `eid` нь `Signer` порт болно |
| `urtuu` | 3 | 2536 | Апп нь салгагдана, тээвэр нь платформд үлдэнэ |
| `sso_clients` | 1 | 601 | Домэйн нь OAuth2 клиентийн бүртгэл; `ssoprovider` нь порт |

`esign` жагсаалтад байхгүй: Ажил 0-д `internal/platform/esign` болсон
тул апп биш. Түүний долоон импорт нь платформ доторх ердийн хамаарал
болно — платформын пакет платформын пакетыг импортлох нь дүрмийн
зөрчил биш.
