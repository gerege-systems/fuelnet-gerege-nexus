# Баримт бичгийн сайт — Documentation site

Энэ хавтас нь [gerege-systems.github.io/open-gerege-nexus](https://gerege-systems.github.io/open-gerege-nexus/)
хаяг дээр нийтлэгддэг сайтыг угсарна.

**Баримтын эх сурвалж нь энэ хавтас биш.** Сайт нь репод аль хэдийн байгаа
Markdown файлуудаас угсрагддаг: `README.md`, `docs/*.md`, `CONTRIBUTING.md`
гэх мэт. Тиймээс баримт засах гэдэг нь Markdown файлаа засахаас өөр юм биш —
энд юу ч хийх шаардлагагүй. Файлууд GitHub дээр хэвээрээ уншигдана.

## Ажиллуулах

```bash
cd docs/site
npm ci
npm run check      # угсраад холбоосуудыг шалгана
npm run serve      # http://localhost:4321
```

## Юу нийтлэгдэхийг хаанаас шийддэг вэ

`build.mjs` доторх `PAGES` жагсаалт. Шинэ баримт нэмэхэд тэнд нэг мөр
нэмнэ — `src` (репо доторх зам), `slug` (сайт дээрх хаяг), `title`, `group`.

Санаатайгаар нийтлэгдээгүй файлууд: `APPSTORE_PHASE2_PLAN.md`,
`APPSTORE_SEPARATION_PLAN.md`, `DOCUMENTS_WORKLOG.md`. Эдгээр нь явагдаж
байгаа ажлын тэмдэглэл болохоос платформ юу хийдгийг тайлбарласан баримт биш.

## Холбоос хэрхэн ажилладаг вэ

Markdown доторх холбоос нь тухайн файлаасаа харьцангуй байдаг ба сайт нь
хавтасгүй тул `build.mjs` холбоос бүрийг гурван газрын аль нэг рүү чиглүүлнэ:

| Холбоос заасан зүйл | Хаашаа очих вэ |
| --- | --- |
| Нийтлэгдсэн өөр баримт | Сайт дээрх түүний хуудас |
| `docs/assets/` доторх зураг | Хуулагдсан файл |
| Бусад бүх зүйл (`LICENSE`, Go код, `.env.example`) | GitHub дээрх файл |

Тиймээс сайт нь өөрөө нийтлээгүй кодоо ч холбож чадна.

## CI

[`.github/workflows/pages.yml`](../../.github/workflows/pages.yml) нь `main`
салбар дээрх баримт өөрчлөгдөх бүрд сайтыг угсарч нийтэлнэ. Pull request дээр
угсралт ба холбоосын шалгалт ажиллах ч нийтлэхгүй — эвдэрсэн холбоос нь
нийтлэгдсэний дараа биш, өмнө нь баригдана.
