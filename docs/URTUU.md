# «Өртөө» — платформ хоорондын үйлчилгээний суваг

Их Монгол Улсын өртөө шуудан: захиаг өртөөнөөс өртөөнд дамжуулж, хүрсэн
эсэхийг нь буцааж мэдэгддэг байсан. Nexus дээр суурилсан платформууд дээд/доод
холбоосоор хэлхэгдэж, урьдчилан бүртгэгдсэн **хүсэлтийн кодоор** даалгавар
доошоо урсаж, биелэлт нь дээшээ буцна.

## 2. Хоёр зарчим, бүх зүйл эднээс гарна

### 2.1 Доод тал л холбогдоно

Дээд платформ доод руу **хэзээ ч** гарахгүй. Доод суулгац галт ханын цаана,
хувийн сүлжээнд, эсвэл түр унтраатай байж болно — дээд талаас эхэлдэг холбоос нь
зөвхөн нэг талаас ажилладаг холбоос болно.

Тиймээс доод тал өөрөө дээд рүүгээ:

- `GET /api/v1/urtuu/exchange/pull` — хүлээгдэж буй дугтуйг татна (25 секунд
  хүртэл нээлттэй барина; `?wait=0` бол шууд хариулна),
- `POST /api/v1/urtuu/exchange/push` — өөрийн шинэчлэлт болон **баталгаа**-г
  илгээнэ.

Каталог sync яг ижил шалтгаанаар pull сонгосон.

### 2.2 Token нь "хэн ярьж байна", гарын үсэг нь "хэн бичсэн"

Хоёр өөр асуулт, дугтуй бүр дээр хоёулаа асуугдана. Хулгайлагдсан token нь
харилцах эрх өгнө, юу ч зохиох эрх өгөхгүй; хуурамч дугтуй нь холбоос
байгуулахад солилцсон нийтийн түлхүүрийг давж чадахгүй.

## 3. Тохиргоо

| Хувьсагч | Хаана | Юу |
| --- | --- | --- |
| `URTUU_SIGNING_KEY` | Суулгац бүр | Энэ суулгацын Ed25519 түлхүүр, base64. 32 байт seed эсвэл 64 байт private key хоёуланг хүлээж авна. **Тавигдаагүй бол Өртөө унтраалттай** — платформ хэвийн асна, зөвхөн сувгийн үйлчилгээ ажиллахгүй |
| `URTUU_ALLOW_INSECURE_PEERS` | Суулгац бүр | `1` бол `http://` хаягтай холбоос зөвшөөрнө. Анхдагчаар унтраалттай: холбоосын token нь `Authorization` толгойгоор явдаг тул http дээр байгуулсан холбоос түүнийг замд байгаа бүх хүнд өгнө. Төрийн хаалттай сүлжээн дэх суулгацууд л үүнийг зориудаар асаана |
| `RING_BASE_URL` | Кодын эх сурвалж | ring.dgov.mn-ий хаяг. `mock` гэж тавибал хөгжүүлэлтийн жишиг кодууд ирнэ (нэр дээрээ «жишиг» гэж бичигдсэн). Тавигдаагүй бол импорт унтраалттай, локал кодууд ажиллана |
| `RING_API_KEY` | Кодын эх сурвалж | Ring-ийн түлхүүр. `RING_BASE_URL` бодит хаягтай бол заавал |

Түлхүүр үүсгэх:

```bash
openssl rand -base64 32
```

**Түлхүүрээ бүү сольж бай.** Түлхүүр солигдвол суулгацын ID өөрчлөгдөж, одоо
байгаа холбоос бүрийн token хүчингүй болж, нөгөө талын хадгалсан нийтийн
түлхүүр буруу болно. Холбоос бүрийн мөрөнд `installation_id` бичигдэж байдаг
тул тэдгээр нь **чимээгүй унтрахгүй** — аль нь хуучин түлхүүрээр байгуулагдсаныг
нэрлэж чадна — гэхдээ дахин байгуулах хэрэгтэй болно.

## 4. Холбоос байгуулах (handshake)

Гурван алхам, хоёр талын зөвшөөрөл (`report_grants`-ийн урсгал):

### Алхам 1 — Дээд тал урина

Тохиргоо → Өртөө → **Доод платформ урих**. Нэг удаагийн код гарч ирнэ:

```
POST /api/v1/urtuu/peers/invite   { "name": "Ховд аймаг" }
→ { "id": "...", "invite_code": "K7QM-3F9X-...", "expires_in_hours": 24 }
```

Код нь **24 цаг**, **нэг л удаа**, **дахин харагдахгүй**. Хадгалагддаггүй —
SHA-256 нь л хадгалагдана. Алдвал холбоосыг цуцлаад дахин урина.

### Алхам 2 — Доод тал буулгана

Доод платформын админ Тохиргоо → Өртөө → **Дээд платформд холбогдох**: дээдийн
хаяг + код.

```
POST /api/v1/urtuu/peers   { "invite_code": "...", "base_url": "https://yaam.gov.mn", "name": "Боловсролын яам" }
```

Энэ үед доод тал:

1. дээдийн `/.well-known/urtuu.json`-оос нийтийн түлхүүр, суулгацын ID-г татна,
2. өөр дээрээ холбоосын мөр үүсгэнэ,
3. дээдийн `/api/v1/urtuu/peers/redeem` рүү өөрийн нийтийн түлхүүр болон
   тухайн холбоосын token-оо илгээнэ.

Token нь **хадгалагддаггүй, гаргаж авдаг**: `HMAC(signing key, "urtuu-peer-token:"+peer_id)`.
Тиймээс доод талд ил нууц үлдэхгүй, дээд тал зөвхөн SHA-256-г нь хадгална.

### Алхам 3 — Дээд тал баталгаажуулна

Тохиргоо → Өртөө дээр хүлээгдэж буй холбоос гарч ирнэ → **Баталгаажуулах**.

```
POST /api/v1/urtuu/peers/{id}/confirm
```

Үүнээс өмнө pull/push нь **403** буцаана (холбоос байгаа, баталгаажаагүй).
Цуцлагдсан эсвэл байхгүй холбоос нь **401** буцаана — цуцлагдсан тал нь өөрийгөө
"хэзээ ч байгаагүй"-ээс ялгаж чадах ёсгүй.

### Цуцлах

```
POST /api/v1/urtuu/peers/{id}/revoke
```

Аль ч тал хэзээ ч цуцалж болно. **DELETE байхгүй**: "бидэнтэй хэн холбоотой
байсан бэ" гэдэг нь хожим асуугддаг асуулт.

## 5. Хүсэлтийн кодууд

Даалгавар **чөлөөт текстээр үүсэхгүй**. Код сонгоно, код нь юу бөглөхийг (JSON
Schema) болон хэдий хугацаанд хийхийг (SLA) өөрөө хэлнэ.

| Эх сурвалж | Хаанаас | Дүрэм |
| --- | --- | --- |
| `ring` | ring.dgov.mn-ээс импортлогдсон | Угтваргүй нэрийн орон зай (`Д-101`) тэднийх |
| `link` | Дээд тал холбоос дээр зарласан | Доод тал засварлаж чадахгүй; `active` тугийг л өөрөө шийднэ |
| `local` | Энд зохиосон | Заавал `local.` угтвартай — схемийн CHECK шаардана |

**Холбоос бүрд тусдаа.** Дээд тал өөрийн багцаасаа тухайн холбоос дээр аль
кодыг нээхээ шийднэ (Тохиргоо → Өртөө → холбоосын **Кодуудыг нээх**). Зарлал нь
бүтэн агшны зураг: хасагдсан код доод талаас автоматаар алга болно. Хоосон
жагсаалт нь бодит зарлал — тэгэж л нээсэн кодоо хаадаг.

Нэр давхцвал (доод тал өөрөө `local.x` зохиосон, дээд тал бас `local.x`
зарласан) **өөрийн тодорхойлолт ялна**.

### Ring импортлогч

`internal/platform/urtuu/ring.go` — интерфэйсийн цаана. Бодит хариултын
**parsing нь одоогоор TODO**, учир нь ring.dgov.mn-ий утасны формат
тохирогдоогүй. Таамгаар бичсэн parser нь өөрийн тестээ давж, бодит цэг дээр
буруу байх учир зориудаар бичээгүй. Юу тохирох ёстойг файл дотор жагсаасан.

## 6. Даалгаврын амьдралын мөчлөг

```
ИРСЭН → ХҮЛЭЭН АВСАН → ХИЙГДЭЖ БАЙГАА → БИЕЛСЭН → (эх тал) ХААГДСАН
              ↘ БУЦААСАН (шалтгаантай)          ↗
              ↘ ЗАДАЛСАН → доод даалгаврууд → бүгд биелэхэд эх нь БИЕЛСЭН
хугацаа хэтэрвэл → ХОЦОРСОН (төлөв биш, туг: аль ч төлөв дээр асна)
```

Схемд хадгалагдах утга нь латин, том үсгээр (`RECEIVED`, `ACCEPTED`, …) —
платформын бусад бүх төлөв тэгж бичигддэг, CHECK constraint, Prometheus label,
тайлангийн шүүлт бүгд түүн дээр тулгуурладаг. Монгол нэр нь толь бичигт
(`frontend/lib/i18n/addons/urtuu.ts`) 7 хэлээрээ байна.

**Задаргаа (fan-out)** нь доод бүрд **тусдаа даалгавар** үүсгэж эхтэйгээ
`parent_task_id`-аар холбоно. Тиймээс "target_peers" гэсэн массив багана
байхгүй: массив байсан бол нэг ажил хоёр газар бичигдэж, хоёр нь зөрөх өдөр
гарцаагүй ирнэ.

**Хэн хийж байгаа нь дээшээ явахгүй.** Дотоод хариуцагч оноох нь тухайн
байгууллагын хэрэг; дээд тал "хийгдэж байна" гэдгийг мэдэх бөгөөд түүнээс
илүүг биш (§2.4).

### Мөчлөгийн хамгаалалт

Даалгавар бүр `origin_chain` авч явна — дамжсан суулгац бүрийн ID. Ирсэн
даалгаврын гинжинд өөрийн ID байвал даалгавар **үүсэхгүй**, шалтгаантай
буцна. А→Б→А гэсэн холбоосын бүтэц өөрөө хууль ёсны (хоёр яам өөр өөр төрлийн
ажлаар бие биенийхээ дээд байж болно) — хамгаалагдах ёстой нь холбоос биш,
**даалгавар**.

## 7. Ажиллагааны runbook

### «Даалгавар доод тал руу очихгүй байна»

1. **Тохиргоо → Өртөө** → тухайн холбоосын мөрийг хар:
   - `Сүүлд холбогдсон` хоосон эсвэл хуучин уу? → доод тал холбогдохоо больсон;
   - `хүргэгдээгүй` тоо өсөж байна уу? → дараалал хуримтлагдаж байна;
   - улаан алдааны мөр байна уу? → нөгөө талын хариу шууд бичигдсэн байна.
2. Холбоос `Идэвхтэй` эсэхийг шалга. `Хүлээгдэж буй` бол дээд тал
   **баталгаажуулаагүй** байна.
3. Доод талын лог: `urtuu: exchange with a parent failed` мөрийг хай.
4. Хүргэлт **exponential backoff**-той (30 сек → 6 цаг). Нэг цагаас дээш
   хугацаанд хүрээгүй бол энэ нь оролдлогын хооронд байгаа гэсэн үг биш.

### «Дугтуй буцаагдаж байна» (`urtuu.rejected` audit)

Гарын үсэг шалгагдаагүй байна. Гурван шалтгаан:

- нөгөө тал `URTUU_SIGNING_KEY`-гээ сольсон → холбоосыг дахин байгуул;
- хадгалагдсан `peer_public_key` буруу → холбоосыг цуцлаад дахин байгуул;
- дунд нь агуулга өөрчлөгдсөн → энэ бол аюулгүй байдлын явдал, аудитыг үз.

### «Даалгавар шалтгаантай буцаж ирлээ»

Ирсэн `task.update`-ийн тайлбарыг унш:

- `origin chain` → мөчлөг. Тухайн салбар руу дахин илгээх утгагүй;
- `has no request code X` → доод талд тэр код байхгүй. Холбоос дээр кодоо
  нээгээгүй, эсвэл зарлал хараахан хүрээгүй байна;
- `is not in use` → доод тал тэр кодыг өөрөө унтраасан байна.

### «Цагийн зөрүү» анхааруулга

SLA-г **илгээгчийн** `created_at`-аар тооцно (§9), тиймээс платформ цагийг
чимээгүй засахгүй — зөрүүг холбоосын мөрөнд бичиж, харагдуулна. 5 минутаас дээш
зөрүү бол нөгөө талын NTP-г шалга.

### Хэмжигдэхүүнүүд

| Метрик | Утга |
| --- | --- |
| `urtuu_tasks_total{status}` | Шилжилт бүр, төлөвөөр |
| `urtuu_deliveries_total{result}` | `ok` — нөгөө тал баталсан; `failed` — солилцоо тасарсан |
| `urtuu_peer_last_seen_seconds{role}` | Хамгийн удаан дуугүй байгаа идэвхтэй холбоос, чиглэлээр |

**Тенантын label хаана ч байхгүй** (MONITORING.md). Байгууллагаар задлах нь
тайлангийн асуулт бөгөөд өгөгдлийн сангаас хариулагдана — тэнд мөр устгагдаж
чадна, Prometheus-ийн цуваа устдаггүй.

Оператор консолын нүүрэн дээр «Өртөө» гэрэл: хүргэгдээгүй дугтуйн тоо, нэг
цагаас дээш дуугүй холбоосын тоо. Оператор **агуулгыг харахгүй** — миграци
`00064` нь зөвхөн `urtuu_peers`, `urtuu_deliveries`-ийг нээдэг.

### Цэвэрлэгээ

| Юу | Хэдий хугацаанд |
| --- | --- |
| Баталгаажсан хүргэлт | 180 хоног |
| Ирсэн дугтуй | 180 хоног |
| Хугацаа дууссан урилга | Цаг тутам кодыг нь цэвэрлэнэ (мөр үлдэнэ) |

Ирсэн дугтуйн хадгалалт нь `urtuu.MaxAge`-аас (7 хоног) хамаагүй урт байх ёстой:
хоёулаа хамтдаа replay-ээс хамгаална — дугтуй 7 хоногийн турш л хүчинтэй,
"аль хэдийн ирсэн" гэдгийг хэлэх мөр нь түүнээс хамаагүй удаан амьдарна.

## 8. Хоёр суулгацыг нэг машин дээр турших

SSO federation-ий баримтад бичигдсэн localhost хосын загвар:

```bash
export URTUU_ALLOW_INSECURE_PEERS=1
export URTUU_SIGNING_KEY=$(openssl rand -base64 32)   # суулгац тус бүрд ӨӨР
```

Integration тестүүд яг үүнийг нэг процесс дотор хийдэг:

```bash
cd backend
URTUU_TEST_DATABASE_URL=postgres://... go test ./internal/platform/urtuu/... ./internal/apps/urtuu/...
```

## 9. Юуг ДАХИН бүтээгээгүй вэ

| Хэрэгцээ | Аль бэлэн зүйл дээр суусан |
| --- | --- |
| Гарын үсэгтэй тээвэр, replay-хамгаалалт | `pkg/catalog`-ийн signed баримтын хэв маяг (`created_at` + түүхий байт) |
| Хүргэлтийн retry, идемпотент | `integration`-ийн deliveries + housekeeping |
| Хоёр талын зөвшөөрөл, цуцлалт | `report_grants`-ийн үүсгэх/зөвшөөрөх/цуцлах хэв |
| Append-only түүх | `installation_events`-ийн хэв |
| Хоёр талын audit | `reports.data_shared` / `consolidated_read`-ийн дүрэм |
| Хуваарьт тайлан, түгээлт | reporting хөдөлгүүр + `reports.schedule` |
